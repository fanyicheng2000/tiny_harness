# `edit-file.js` 详细讲解：局部安全编辑与四级模糊匹配

`EditFileTool` 用 `old_text → new_text` 局部替换修改已有文件。相对 `write_file` 全量覆盖，它减少了模型误写大文件的影响范围；相对严格字符串替换，它通过四级渐进匹配容忍模型常见的缩进和换行偏差。

## 工具契约

工具名为 `edit_file`，要求：

- `path`：已有文件路径；
- `old_text`：待替换旧片段，要求足够上下文确保唯一；
- `new_text`：替换后的文本。

编辑前使用 `resolveWorkspacePath()` 和 `assertExistingPathInsideWorkspace()`，因此同时防普通路径逃逸和既有符号链接逃逸。

## 执行流程

1. 校验并读取原文件；
2. 调用 `fuzzyReplace(originalContent, oldText, newText)`；
3. 将新内容写回同一路径；
4. 返回成功确认，或抛出可被 Registry/Recovery 处理的错误。

任何读取、匹配、写回失败都会保留语义化错误文本，模型下一轮可据此重新读取或增加上下文。

## 四级匹配链

### L1：精确唯一匹配

先统计 old_text 出现次数：仅出现一次才替换；多次出现直接报错，避免误改。

### L2：换行归一化

将 `\r\n` 统一为 `\n` 后再唯一匹配，处理 Windows 与 Unix 换行差异。

### L3：首尾空白容错

对 old_text 使用 `trim()` 后匹配，处理模型复制片段时带入的首尾空行/空格。它不忽略中间行差异。

### L4：逐行忽略缩进

将 old_text 每行 trim，再在文件行数组上做滑动窗口匹配。仍要求恰好一处匹配；命中后用“原文件前段 + newText + 原文件后段”拼接结果。

越往后容错越强，也越可能误匹配，因此每层都坚持唯一性检查。这是本工具最关键的安全原则。

## `countOccurrences()` 与唯一性

函数逐次使用 `indexOf` 计数，移动下标时跨过 needle 长度，因此统计不重叠出现次数。空 needle 特判为 0，避免无限循环或把空串视为无数匹配。

## 边界与改进

- L4 忽略每行缩进，可能不适合 Python/YAML 等缩进语义敏感文件；可按文件类型限制该降级层。
- 没有备份、diff、原子写入或版本检查；并发编辑同一文件可能覆盖更新。
- `new_text` 不会自动继承匹配片段缩进，模型应自行提供正确格式。
- fuzzyReplace 未导出，单元测试只能通过工具接口间接覆盖；可导出纯函数提升测试颗粒度。

## 总结

`edit-file.js` 将“模型的近似文本理解”转为“受唯一性约束的局部修改”。它在可用性和安全性间分层折中：先严格，再逐步容错，始终拒绝不唯一的编辑。
